# OPCB UI Standard v1

状态：供插件适配与验收使用的设计标准候选。基础实现值由 OPCB 明确定义，来源观察与未知边界见 [EVIDENCE.md](EVIDENCE.md)。建立标准不代表仓库内全部插件已改版、已安装或已通过实机验收。

适用范围：Buzz 原生插件的业务内容区域，以及由 OPCB 维护且允许修改的内嵌 Web 界面。宿主身份、权限、聊天、安装审核、窗口与系统控件继续使用 Buzz 原生能力。

## 1. 五行方向

**产品**：为 OPCB 各插件提供同一种资料浏览、任务处理与业务配置语言，让用户在切换工具时保留操作经验。

**性格**：安静、明确、有内容感。

**场景**：桌面与 iPad 上的日常工作；在宿主分屏或窄面板内也能快速定位当前对象。

**重点**：真实资料预览、当前工作对象、可核对的结果与来源承担主要视觉表现。

**识别细节**：深色框架中放置有清楚边界的工作面；选中与属性沿用相同的形状、位置和语义。

Woday 是主要结构与视觉参考，Sphere 补充宽屏集合与当前内容并存的关系。采用规则和组件的方式借鉴；品牌图标、原作封面与业务内容不成为 OPCB 的默认素材。

## 2. 范围与宿主边界

### 2.1 业务区域统一

所有标准样式收敛在根节点 `.opcb-ui` 内。主题、字体、间距和组件样式不得泄漏到 Buzz 的聊天、原生侧栏或其他插件。页面可以使用相同的组件语言，不要求所有插件具有相同的信息架构。

根节点承担主题、密度和容器宽度的边界。使用本目录的 Token 与组件样式，不在页面中为同一角色重复定义另一套颜色、字号或圆角。需要扩展时先增加语义或组件变体，再由页面采用。

### 2.2 原生、iframe、BrowserView

| 承载方式 | 应用位置 | 集成限制 |
| --- | --- | --- |
| 插件自己的 HTML/业务 DOM | `.opcb-ui` 内 | 样式必须作用域化；不依赖宿主私有 DOM 或私有状态 |
| iframe 内的自有页面 | iframe 文档自己的根节点 | 外层 CSS 不穿透 iframe；通过已公开、允许的方式传递主题，必要时由内页分别加载相同 Token |
| BrowserView 或独立远端业务页 | 该页面可维护的业务代码 | 需要页面维护权和正常交付；外框改色不能算远端内容已适配，不以跨域注入绕过边界 |
| Buzz 原生设置、审核、菜单、窗口 | 宿主提供的组件或公开主题能力 | 不复制宿主窗口控制、聊天、系统返回或安装审核；未开放的样式能力记录缺口 |

不新增虚构的宿主 API。各插件只能使用当前官方 SDK 已公开的主题与生命周期机制；无主题事件时标明限制，并以可用的系统主题回退。不得读写宿主私有注册表或改造宿主核心来套用本规范。

## 3. 布局槽位

统一六个语义槽位，按模板组合，不固定同时显示：

| 槽位 | 职责 | 约束 |
| --- | --- | --- |
| 框架 | 承载插件内部导航与工作面间隙 | 不复制系统窗口外壳；颜色安静，避免承载大量业务字段 |
| 导航 | 内部集合、视图、收藏或设置分类 | 224px；仅当它提供宿主导航之外的实际定位价值时使用 |
| 工具栏 | 页面标题、范围、筛选、视图与主动作 | 对同类任务位置一致；主动作最多一个视觉主次最高的按钮 |
| 主工作面 | 当前浏览、操作或阅读任务 | 可变宽；圆角20px；内容按任务选择列表、卡片、表格或正文 |
| 辅助工作面 | 当前对象预览、详情、收件区或来源 | 320px；属于当前主任务；同一槽位优先显示一种内容 |
| 浮层 | 菜单、选择器、快速入口、确认 | 依附触发对象；可关闭；不替代必须长期查看的信息 |

工作面间距为12px。内部主要空间使用4/8/12/16/24/32/48px，允许为图标光学校准使用2px。主工作面边距一般24px，阅读或宽屏重点内容可用32px，窄屏可降为16px。

相同角色使用相同尺寸；内容长时允许组件增高，不截断关键事实以维持固定高度。列表第二行信息与标题对齐，不与前置图标对齐。

## 4. 六种页面模板

### T1：集合与总览

适用：知识库首页、素材集合、工作区、结果报告入口。

顺序为“页面范围→返回当前工作的入口→有辨识度的集合或对象”。集合展示名称、内容范围和必要预览；缺少真实图片时使用文字或类型图标。选择集合进入其对象列表，不在首页展开全部正文。

默认集合布局按真实内容密度选择列表或网格。首页允许较大留白，但不能为了装饰制造空白大横幅、泛化口号或大量空卡片。状态如“未同步”“暂无资料”直接可读。

### T2：列表与详情

适用：资料检索、任务、邮件、成员、账号或审计项。

列表默认显示标题、最多一行摘要和必要属性。当前对象具有明确选中态，辅助工作面显示对应详情或预览。关闭详情后保留选中、筛选、排序与滚动位置。没有选中对象时显示任务相关的提示，不伪造详情。

行级主动作与多选分离；不要把整行按钮内部再嵌入互相冲突的按钮。批量模式需要显示已选数量和可执行动作，退出后回到正常浏览。

### T3：专注内容

适用：文档、研究、笔记、素材详情、完整报告。

标题、来源、更新时间与属性先于正文。正文占主工作面，辅助面板默认可关闭；大段阅读不挤在列表下方。正文使用章节、段落、表格与引用组织，不为每段增加卡片。

阅读宽度以可读性为准，建议正文最大宽度从约44个汉字的阅读尺度开始验证。图表与表格允许在其区域扩展。真实来源、AI 摘要与原文分别标注；没有音视频原件时不显示假播放器。

### T4：看板与时间视图

适用：任务流程、资料整理、排期、研究阶段。

列的含义必须来自业务：状态、阶段、负责人或日期只能选择实际存在的维度。日期分列不能标为状态流程。列头含标题与数量，卡片以对象标题为主，保留必要状态与归属。

列表、看板、日历是可选视图；只有真实数据与业务模型支持时才提供。切换视图保持筛选与范围。看板允许内部横向滚动，不让整个页面溢出。拖放必须有键盘或菜单替代，只有真正支持状态更新时才允许拖动提交。

### T5：数据与比较

适用：经营数据、库存、指标报告、批量对象属性。

表格优先保证同列数据可比较，数值使用统一格式与等宽数字。口径、单位、数据截止时间、筛选范围容易找到；不以空白代替零，不以零代替未知。

图表必须解释实际问题，颜色具有稳定序列语义。主要指标不做同等重量的大卡片铺满页面。小屏在表格区域横向滚动，并保留必要行列标识；整体页面无横向溢出。

### T6：配置与管理

适用：人员权限、连接、插件配置、偏好与导入。

左侧分类或顶部标签负责定位，主工作面按目标分组字段。字段有标签、当前值与必要说明；一个控件表达一个明确操作。保存时显示进行中，收到业务成功回执后才显示已保存。

权限开关不得仅依靠颜色。需要审批或原生确认的动作继续走对应流程。管理对象、审计记录与普通阅读分开；撤权、失败、过期与未配置具有不同文案和可执行恢复路径。

## 5. 文字层级

默认基础字体为系统无衬线，中文使用系统回退。仅内容标题允许可选 `ui-rounded`；不能要求系统控件或全部中文正文都使用同一种 Rounded 字形。

| 角色 | v1 设计值 | 使用约束 |
| --- | --- | --- |
| 页面/主内容标题 | 32px / 600 | 每个主要工作面一个；窄屏可自然换行 |
| 对象标题、列表正文、主要控件 | 16px | 用字重区分主次，不用多个强调色抢夺注意 |
| 摘要、元信息、字段说明 | 14px | 保持可读对比度；不承载唯一关键结论 |
| 长文正文 | 18px / 行高1.75 | 中文阅读基准；随系统放大保持可用 |
| 分组和章节标题 | 使用组件规定的中间层级 | 不与页面大标题争夺主次；不得各页面随意增加字号 |

数字、单位、日期、截断和空值格式在插件内一致。标题以完整理解优先；必要截断提供可触达的完整值。工具提示不能作为触屏用户获取关键事实的唯一方式。

## 6. 色彩语义与主题

### 6.1 语义层

颜色经过“基础色板→语义角色→组件状态”三层。页面使用语义，不直接按个人偏好挑选色值。

| 角色 | 用途 | 约束 |
| --- | --- | --- |
| 框架与工作面 | 导航、主面板、副面板、次级表面 | 保持层次；避免多重阴影与装饰渐变 |
| 主要/次要/辅助文字 | 结论、对象、属性与说明 | 所有主题中分别通过对比度验收 |
| 主动作 | 用户当前最主要且可执行的操作 | 深橙`#b33124`配白字；必须有具体动作文案 |
| 装饰强调 | 当前日期、少量图标或对象识别 | `#f24f3d`；不能默认作为白字按钮背景或关键小字号文字色 |
| 成功/警告/危险/信息 | 业务或系统状态 | 同时使用文字或图标；危险动作不等同于普通主动作 |
| 主题/类别标签 | 对象所属主题、集合、类型 | 与错误/授权/保存状态分离，类别名称始终可读 |

选择态和键盘焦点是两个状态：选择表示当前对象，焦点表示键盘下一次操作目标，二者可以同时存在。不能只更改颜色而没有轮廓、背景或可访问状态。

### 6.2 三种主题

提供 `light`、`dark`、`host`。它们是规范主题模式，不宣称是某一版本 Buzz 的实际属性名称或 API。

- `light`：维持深色插件框架和浅色工作面的参考关系；辅助表面轻于边界。
- `dark`：用深浅不同的深色表面与足够亮度的文字重建层级；不机械反相，不保留刺眼大白面板。
- `host`：优先消费宿主公开的主题语义；需要映射时在适配层集中映射。宿主无法提供的值才使用对应系统主题的本地回退。

`host`不能靠检测宿主私有 DOM 猜测主题。插件和内嵌页之间传递主题只使用允许的接口与明确来源；跨域页面不自动继承外壳 CSS。每种实际承载方式分别验证。

## 7. 组件结构

### 7.1 共同对象结构

一个对象由身份、内容、属性、状态与动作组成。相同对象跨列表、卡片、看板和问答来源卡时，保持标题、类型与关键状态一致。

| 组成 | 最小内容 | 规则 |
| --- | --- | --- |
| 身份 | 稳定ID、类型、标题 | 不以数组位置充当长期选择身份 |
| 内容 | 摘要或真实缩略图 | 没有内容时如实省略；图像不是所有对象的必选字段 |
| 属性 | 来源、时间、所属集合或业务维度 | 优先级固定；至少能确认当前对象来自哪里 |
| 状态 | 选择、完成、同步、权限或错误 | 各有独立事实来源，不互相推断 |
| 动作 | 打开、预览、编辑或菜单 | 显示条件与业务权限一致；只读对象不伪装可编辑 |

### 7.2 v1 组件职责

| 组件 | 内容/槽位 | 必须覆盖的行为 |
| --- | --- | --- |
| 导航项/分组 | 图标、名称、可选计数 | 当前项、折叠、长名称、键盘到达 |
| 页面工具栏 | 标题、范围、筛选、视图、主动作 | 窄屏换行与溢出菜单；不遮挡标题 |
| 按钮/图标按钮 | 动作文本或可访问名称 | hover、focus、pressed、disabled、busy |
| 标签/状态标记 | 名称、可选图标或计数 | 类别与状态区别；长文本不破坏行高 |
| 对象行/卡片 | 身份、摘要、属性、状态、动作 | 选择、预览、只读、批量、缺图与长标题 |
| 详情工作面 | 标题、属性、正文/表单、关闭 | 对应选中对象；替换和关闭后焦点可预测 |
| 输入/选择/开关 | 标签、值、说明、错误 | 有标签；有更改、待保存和保存失败反馈 |
| 搜索/快速入口 | 输入、范围、结果、动作提示 | 未输入、加载、无结果、错误、键盘选择 |
| 来源卡片 | 结论关联片段、原题、来源与时间 | 能打开出处；未检索来源不伪装已覆盖 |
| 空错加载状态 | 状态说明、可执行下一步 | 区分空集合、无结果、加载中、无权限与失败 |

组件视觉应从 Token 与共用样式获得。组件可用原生 HTML 实现，不要求所有插件引入同一前端框架。图标使用统一线性图标语言；内容对象允许真实封面或识别图，系统导航不滥用Emoji。

## 8. 状态矩阵

| 状态 | 视觉与文案 | 行为/语义 | 不得混淆 |
| --- | --- | --- | --- |
| 默认 | 正常表面与文字 | 可执行动作可到达 | 默认不代表已保存 |
| hover | 轻微表面或边界变化 | 不改变布局与业务事实 | hover不是选中 |
| focus | 持续、可见的轮廓 | `focus-visible`；不被面板裁切 | 焦点不是当前对象 |
| selected/current | 背景或边界及明确当前语义 | 适当使用`aria-current`/`aria-selected` | 选中不代表授权 |
| pressed | 清楚的按下反馈 | 按钮语义与实际状态一致 | 按下不是请求成功 |
| disabled/readonly | 保持可读，必要时说明原因 | 使用原生禁用或明确只读语义 | 只读与无权限不同 |
| loading/busy | 说明正在处理的对象或操作 | 防重复提交；结果区域`aria-busy` | 不显示虚构完成数 |
| empty | 说明集合为空或尚未接入 | 提供有效入口或明确下一步 | 空集合不同于失败 |
| no-results | 保留查询与筛选，说明无匹配 | 可清除筛选或修改查询 | 无结果不同于全库为空 |
| error | 人可理解的原因与恢复动作 | 保留已输入内容；可重试时才展示重试 | 错误不覆盖已有真实数据 |
| no-permission | 说明具体受限范围 | 由原权限流程处理 | 不切身份、不以缓存绕过 |
| pending-save | 显示待保存或提交中 | 可取消/防重复；按业务契约执行 | 不提前显示已保存 |
| saved | 成功回执与必要更新时间 | 回读或持久化证据支撑 | 本地样式变化不是保存 |
| stale/partial | 标明时效或实际覆盖范围 | 可继续查看可用部分 | 部分结果不称完整搜索 |

状态组合要有明确优先级：无权限/错误信息不能被hover覆盖，焦点始终可见，保存失败保留编辑内容。状态提示不只靠颜色。

## 9. 容器响应与返回路径

断点以 `.opcb-ui` 可用容器宽度为准，不能用整台设备屏幕宽度推定。Buzz侧栏、分屏和内嵌边距会减少插件实际空间。

| 容器宽度 | 布局行为 | 关键约束 |
| --- | --- | --- |
| ≥1100px | 可显示224px导航、主工作面与可选320px详情 | 详情是可选槽位；主内容不能因为空详情而被永久压窄 |
| 780—1099px | 收起内部导航，保留主工作面与可选详情 | 提供明确导航入口；大字号或长内容时允许提前进入单工作面 |
| <780px | 详情替代主内容，一次显示当前主要任务 | 返回恢复列表、查询、筛选、选择与滚动；正文不堆到列表底部 |

固定宽度之外的主工作面需要`min-width:0`等收缩约束；长中文、URL、代码、标签与表格分别处理。表格/看板的横向滚动限制在自身区域，整体页面无横向溢出。

导航、搜索、筛选、详情和浮层的开闭状态需要明确归属，避免一个按钮同时改变不相关区域。屏幕变窄时不丢失未保存内容；恢复宽度后不自动提交业务操作。

## 10. 触屏、键盘与辅助技术

### 10.1 触屏

交互命中区域至少44×44px，图标字面可小于命中区域。行内按钮不得覆盖标题点击区。触屏能够访问所有关键操作，不以hover工具提示或hover尾部菜单为唯一入口。iPad分屏和大字模式分别验收。

### 10.2 键盘与语义

使用真实`button`、`input`、`label`、`select`等元素；图标按钮有名称，表格有表头。Tab顺序与视觉任务顺序一致。打开详情或对话框后焦点可预测，关闭后回到触发入口或有效相邻对象。

真正的模态对话框管理焦点并阻止背景交互；普通辅助面板不伪装成模态。Esc关闭当前可关闭层，不丢弃未保存内容或扩大为页面退出。非模态列表不强行设置焦点陷阱。

选择器、菜单和组合框仅在实现相应键盘交互时声明对应ARIA角色；不用角色名称替代实际行为。加载与保存消息采用适度的状态播报，不重复打断阅读。

### 10.3 对比与放大

普通文字至少4.5:1；大文字至少3:1；关键控件边界和焦点可辨识区域至少3:1。每种实际主题校验，不根据色名判断。辅助文字不得因为“淡”而不可读。

200%文字放大后仍能访问主要动作，关键文本可换行；避免固定高度截断标签与错误说明。不能只用颜色区分类别、权限、失败和完成。

### 10.4 动效

只用动效说明状态与空间关系。hover/按下反馈短，面板/菜单出现温和；不使用循环漂浮、跳动卡片、装饰发光或全属性过渡。

支持`prefers-reduced-motion: reduce`：移除非必要移动与缩放，保留立即可见的状态反馈。不得为了动效延后关键业务反馈；不动画布局宽高造成持续重排。

## 11. 业务真实性与内容规则

同一设计不等于同一业务能力。当前数据、权限、同步与保存事实来自各插件原本服务和公开宿主 API，不能由视觉状态推断。

1. 演示数据显著标注；不把示例计数、收入、完成率或成员授权当作真实事实。
2. 未接入、未同步、过期与无权限分别说明；保留来源与数据截止时间。
3. 知识问答区分检索范围、AI整理与原文；来源卡片可回到真实出处。
4. 破坏性、跨权限和原生审核动作按原流程处理；样式迁移不扩大操作授权。
5. 没有原件时不虚构图片、封面、音视频播放器或预览能力；真实内容缺失时采用诚实的文本状态。

## 12. 跨插件一致性与允许差异

### 必须一致

语义Token、文字层级、空间基准、主按钮、图标语言、标签与状态区别、选中/焦点、工具栏主次、详情开闭、空错加载、容器响应和无障碍最低要求。

### 允许不同

任务中心选择看板，知识库选择阅读，素材库选择图文集合，经营数据选择表格。内容类型、字段、业务层级、默认密度和主动作可以不同。相同对象和相同动作的表达不能在插件之间无故变化。

`comfortable`和`compact`允许作为同一体系的密度变体；不通过全局缩小字体压入更多信息。阅读正文始终使用专门尺度。已有特殊可视化如关系图、流体主题或编辑画布可保留，但其工具栏、属性、状态和返回路径应采用共用语言。

纯连接器没有独立业务界面时，只在其可维护的配置或反馈区域应用标准；不为“全部统一”制造无必要页面。外部网站无维护权时记录为待适配边界，不声称外框相似即完成。

## 13. 版本治理与采用流程

规范、Token、组件和示例以同一版本目录维护。`v1`定义主要视觉与交互契约；发布说明记录设计版本、实际代码提交、验证范围、未覆盖平台与受影响插件。

| 变更类型 | 处理规则 |
| --- | --- |
| 修正文案、对比度或不改变契约的错误 | 补丁记录，指出影响的角色与验证 |
| 增加向后兼容的Token或组件变体 | 次版本说明，并给出使用示例 |
| 改名/删除Token、改变布局断点或默认行为 | 作为破坏性变更提供迁移说明；不能静默覆盖已采用插件 |
| 插件业务字段、权限或服务行为改变 | 按各插件业务版本单独处理，不伪装成纯视觉更新 |

每个采用插件记录：设计版本、采用模板、承载方式、宿主版本/API、目标平台、验证提交和未验收项。不要只依据相同CSS文件名判断采用完成。

推荐先验证知识库的列表/正文和一个管理界面，再覆盖任务看板、素材集合与数据表格。完成一类样板后复用到其余插件，保留原服务与用户数据。正式目录、分发包和安装审核按仓库规则逐项完成；建立本标准不自动切换REGISTRY默认版本。
