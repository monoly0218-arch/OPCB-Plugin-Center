# 知识库管理 2.0 候选（rc.4）

插件 ID `opcb.knowledge-admin`，原生API v1，个人管理员专用。按Buzz个人公钥管理库/子库读取权限、个人停用/恢复、名称、子库目录与审计；其Agent自动继承读取权限，无需逐个登记。管理权限不继承给Agent。

管理员资格仅由服务器启动配置指定，安装此插件不会自动成为管理员。首次使用选择可写私人对话，保存仅含设备公钥/挑战的原生签名绑定记录，无密码与12小时登录；使用独立管理设备钥匙，读绑定不能调用管理接口。

自动载入已配置人员与当前社区可见身份（最多200项），按姓名搜索和选择；公钥作为详情和备用查找入口。已配置人员不会因可见身份分页而消失。姓名仅作显示，授权绑定完整公钥。库权限默认关闭，父库关闭覆盖子库允许；“继承上级”移除本库显式规则。停用个人拒绝该人的所有后续读取及所属Agent读取，不改Buzz账号或社区成员。并发保存冲突需刷新后重试。

新增子库只创建权限目录，不自动采集或导入资料；源映射由受控服务维护。改名不更改原GetNote库名。目录中的库名与阅读页由同一服务器策略提供。

仅声明现有知识域名网络权限，无宿主命令权限，无Agent管理工具。依赖中心services/knowledge身份服务；构建源src/knowledge/admin.mjs，使用npm run build:knowledge。官方/本机版本参考、候选测试与平台边界同阅读插件：v1.0.1/macOS ARM64，rc.1真实管理身份绑定与权限保存已在Studio验证，rc.4更新后的原生验收仍待，Android/iOS未验证。

固定中心来源和完整commit生成原生安装审核卡，保留本人最终批准。已读信息无法追回，撤权保证后续请求按新ACL检查。不得把本地模拟测试当作生产授权已生效。

## rc.4 管理路径重构

默认先看已配置人员总览：姓名搜索、权限范围与停用状态；进入个人详情后逐库调整允许/关闭/继承。可以取消筛选查看其他社区可见身份，或用完整公钥查找。只查看、搜索和切换不会自动开通权限。

增加按知识库出发的总览和详情：先选一个库，再直接查看及调整人员的读取权限。名称层级和审计为次要入口。保留实际可读状态与显式规则的区别、父库关闭覆盖子库、服务器每次鉴权与版本冲突检查，不重置现有人员授权与管理设备钥匙。

封面与阅读插件共用同一业务视觉语言。rc.4 是结构重做后的候选，不把旧 rc.2 的审核或演示检查当作本次原生安装验收。


rc.4 同步综合知识库身份客户端构建；没有新增 Agent 管理权限。“收藏与产物”仅在服务显式启用后出现，管理员沿用已有库读取授权。读授权不允许使用读设备上传；入库另需 collect 贡献绑定，数据仍按所属个人隔离。
