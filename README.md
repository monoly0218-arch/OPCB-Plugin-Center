# 安卓通知桥 0.1.0 候选

通过 Buzz 原生插件提供电脑发送端，配合安卓候选0.2.8+18接收。需要电脑在线、Node.js 18+、当前社区实时消息/已读 API，以及手机 ntfy 无 Firebase 版。首次配对后打开一次 ntfy，允许通知和后台运行，再等待新消息；注册成功本身不证明公网订阅已连接。官方参考API为block/buzz-app v1.0.2；当前设备实际支持情况须安装审核后回读，不能从目录存在推断可用。

1. 从正式插件中心的固定分发提交进入原生安装审核，本人确认后启用。插件会启动已声明的Node辅助进程；不会安装Node或更换桌面宿主。
2. 安卓后台通知设置生成配对码，复制到电脑此页，选择最多20个需要提醒的会话，点击保存配对并启用。
3. 配对保存在本机 `.buzz/plugin-data/opcb.android-notifications`，按账号和社区隔离、文件0600、原子替换；不上传配对码，不读取或保存Nostr私钥、Cookie、聊天数据库或消息正文。
4. 电脑通过宿主已验证的实时消息入口接收新消息，遵循频道静音、提及、已读与正在阅读状态，不扫描历史。按会话合并短时洪峰；内部Agent协调、自发消息与过期消息不转发。
5. RFC8291 aes128gcm加密后，仅POST到本人配对的 `https://ntfy.sh/...?...up=1` 端点。HTTP成功仅表示服务接受，手机真实送达在安卓设置里核对。结果未知不会自动重复发送。停用并移除配对删除本插件自身配置；已发送的提醒仍可能到达。

插件的停用、账号或社区切换会停止当前订阅和辅助进程；再次启用按本人已保存的当前账号/社区配对恢复。撤销频道访问后不再转发该频道；手机撤销配对会使旧设备订阅失效。代码与本机配置分开，配置不随分发包提交。

## 验证与边界

完整检查 `npm run ci`。独立测试覆盖静音/已读/内部消息过滤、RFC8291加解密、存储隔离、重复投递、失败不自动重发以及进程退役。实际桌面安装、真实账号及K Pad后台/锁屏验收需分别记录。测试用合成账号和隔离数据，不向真实团队频道发消息。

源码文件client.js和sender.cjs供审阅；plugin.js是将两者固定内联后的可安装模块。业务更新不要求重新构建Buzz桌面宿主；安卓原生能力升级仍需要相应APK。
