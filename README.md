# 工作看板 2.0.0 候选版

公司分工与任务共用一个工作区。按用户提供的 Woday 参考实现黑色侧栏、白色主面板、紧凑任务行和右侧 Inbox／任务详情。保留 OPCB 名称，演示任务和参考图装饰不进入业务数据。

## 数据与交互

- 当前账号读取原工作进度群 Canvas 的人员分工。负责人、工作内容和交付原文来自该频道；缺少排期的任务留在 Inbox，初始状态为待办，不推断已经执行或验收。
- 今日、即将到来、日历、全部任务、重要任务、笔记和事件；支持列表／日期分栏、搜索、负责人筛选和已完成筛选。日历按明确登记的时间展示，未登记时间的当日任务单列。
- 新增任务、完成／重新打开、编辑负责人／优先级／日期／时间／工作内容／交付；笔记和排期事件同样写回原 Canvas。
- 第一次保存会在原文末尾附加工作区区块。之后只替换该区块，保留原计划和来源正文；区块含可读任务表及版本化 JSON，Canvas 是唯一共享任务来源。
- 当前界面复用已有私人 Solo 原生会话入口。未实现远端 Agent 工具通道，也没有独立下载／安装 API。

## 回写协议与权限

要求当前宿主提供 `session.canvas.write(channel, content, {expectedRevision})` 和 `session.canvas.recover(channel)`。本次安卓候选 0.2.7+17 提供此受限接口；官方桌面 API-v1 尚未确认具备同名写接口，不能据此声明桌面插件已支持写入。无接口时保存会明确报错，不建立本地替代任务账。

原生侧固定工作进度频道、检查当前账号和成员权限，使用宿主签名发送 kind 40100，带 `expected-revision`，强一致读回。遇到版本冲突保留编辑；重新读取后仅提交本人改动的字段，同一字段被其他人修改时要求核对。待核对的已签名事件先持久化，再发送；断线后只核对或重发同一签名，不自动生成另一份任务。

需要服务端 Canvas CAS 前置条件与 writer 强一致读支持。协议源码有对应实现；正式服务器的并发写入效果及 K Pad 真实账号流程仍需实际验收，不以隔离测试代替。

新版权限包含共享写入，需重新审核准确代码摘要。插件没有任意频道读写、任意事件发布、外部网络、安装或账号密钥访问能力。不得为了测试修改真实团队 Canvas。

## 验证

`npm run ci` 执行全部插件中心测试和包校验。模型回归使用合成分工；安卓原生协调器回归覆盖 CAS 冲突、原文保护、权限撤销、持久化失败和丢回执恢复。浏览器与 WebView 验证另行记录，不能替代真人使用验收。
