# 公司看板 · 2.0.0-rc.17

延续已认可的黑色人员卡及rc.16人员同步。按潘涛本轮要求，所有人员固定显示今日工作进度和唯一一条进度条；暂无进度记录时显示0%，已有数值按原实际数值显示。仅调整显示口径，底层缺失记录不伪造成任务完成、已核对或验收。

## 数据接入

1. 看板设置：负责人可依据本人的明确指令，同步当前来源成员的状态和当前事情；记录人员公钥、设置人、代录Agent、原指令链接、时间。保存在原工作Canvas的独立人员同步段，不改任务正文或执行事实。
2. 本人状态：继续订阅原生 session.statuses。看板设置与原生状态按有效时间取新，状态清空可恢复原生值。不会以他人的身份发布原生个人状态。
3. 当前事情：读取真实进行中/受阻任务，补上有真实执行回执的人员分工项；无回执的职责仍不当作实际开工。负责人明确设置的当前事情，与任务回执按时间取新；手工当前事情只在北京时间当天有效。其他成员的Agent活动不等于本人正在工作。
4. 同步入口：opcb_company_people 支持read/update。写入先读baselineRevision，核对本人原始指令、调用Agent与本人会话、当前来源及目标成员权限，使用原生Canvas compare-and-save。相同字段重试幂等，同一原指令下可更新/清空新的当前事情；多个写入原子保存。只有来源负责人可以代其他人设置；普通成员仅本人及其调用Agent。

接口示例（身份与版本均须从当前授权来源读取）：

```json
{"action":"update","expected_revision":"当前完整Canvas版本","request_id":"本轮本人原始指令ID","updates":[{"person":"当前成员公钥","status":"居家办公","current":"正在处理的实际工作"}]}
```

status/current 可设 null 清空；一条记录不改另一字段。同步工具不改个人资料、任务进度、完成、验收、权限或其他插件。随新工具提供的Agent说明只允许按当前授权及真实执行回执同步，不代替执行授权。

页面沿用现有30秒刷新、原生状态订阅与来源实时信号；切账号、撤权及关闭页面释放监听并清理展示。字段缺失显示未同步；进度不由聊天内容或工作状态猜测。

## 验证与分发

官方与Studio为Buzz1.0.2/APIv1；继续使用现有Canvas、profiles、statuses、media、agents、thread能力，无新增host权限，保留现用3D图标。构建 node scripts/build_company_board.mjs，完整检查 npm run ci，打包 python3 scripts/package_release.py。测试覆盖来源保留、状态优先级/清空、北京时间过日、有效开工分工、重复提交、当前事情更新/清空、原指令、CAS与撤权。

分发不含真实人员名单、照片、状态或私有工作快照。候选更新使用正式插件中心固定提交的Buzz原生审核卡；安装和实机业务验收分别核对，不以预览代替原生加载验证。
