# 团队日历 1.0.6 框架版

**当前验收：本机已实现范围通过，完整团队流程尚未全部通过。** 完整 31 项测试通过，双用户个人筛选、会议范围与冲突恢复已在独立测试库完成浏览器实测。插件已热更新到本机 Buzz，原生工具读取成功；原生页面的完整视觉与点击流程本轮未复验。详见 [当前验收报告](docs/ACCEPTANCE_V106.md) 与 [更新说明](docs/RELEASE_V106.md)。下方版本章节为历史记录；状态有差异时以当前报告为准。

沿用 Buzz 的语义表面、文字、选中态与中性色主按钮。以成员为行、日期为列，汇总多个项目的每日和整月安排；项目色用于区分类目。

## 已实现

1. 团队周历、每日安排和团队月历；月历支持「按日期」网格与「按成员」排期。成员/项目筛选、搜索及待安排区继续共用数据。
2. 任务详情、负责人和状态编辑、截止日期、多日期安排、拖动改期，以及项目和成员管理。
3. 周计划导入；同一来源任务保持稳定身份，多天安排引用同一任务，重复导入更新已有记录。
4. 界面、Buzz 插件工具及独立 MCP stdio 共用同一 SQLite 服务；包含版本冲突、重复请求回执、权限校验和实时更新。
5. 浅色、深色预览与窄屏每日列表。Buzz 内沿用宿主表面和文字颜色，不安装全局样式或第二套导航。

## 运行

要求 Node.js 22.13 或以上（本轮为 22.23.1，使用内置 `node:sqlite`）。交付包已包含构建结果，启动不需要安装依赖。

在本目录执行：

```sh
node scripts/setup.mjs
node server/main.mjs
```

打开 `http://127.0.0.1:4177`。默认首次创建无示例任务的工作区，数据库与本机连接配置保存在 `.runtime/workspace/`。默认成员 Moo 和项目“团队事务”可在管理面板修改；尚未读取真实团队数据。

原示例仍保留：执行 `npm run start:demo`，打开 `http://127.0.0.1:4176`；使用独立的 `.runtime/` 数据库。两种模式互不修改数据。模块和接入约定见 [框架说明](docs/ARCHITECTURE.md)。

已有数据库不会被重新初始化。不要通过删除数据库来切换工作区；可用 `CALENDAR_DATA_DIR` 指定另一独立目录，并用同一环境运行 `scripts/setup.mjs`。客户端可通过 `--config` 或 `CALENDAR_CONFIG` 明确选择该目录的 client.json。

## 安装到 Buzz

先启动本机服务，再打开 Buzz 的 Settings → Plugins → Manage plugins → Add → Browse，选择本目录下的 `plugin` 文件夹，审核后安装。必须使用 Browse，拖入会复制文件夹。首次安装由拥有者在宿主界面审核，工具不能代替这次审核。

插件会注册“团队日历”页面和三个工具：`team_calendar_read`、`team_calendar_write`、`team_calendar_operation`。本版 Buzz 工具仅授权当前设计团队日历会话和 MooStudio；其他 Agent 或会话被拒绝。本机已安装并验证原生工具读取；原生页面的完整视觉与点击流程仍需单独验收。

插件仅请求两个声明过的本机 Node 入口：一次性日历请求，以及实时变更订阅。连接凭据留在 `.runtime/workspace/client.json`，不放进 manifest，不上传到聊天。卸载插件会退役工具并结束订阅进程；本机服务由启动它的终端单独管理。

## 独立 MCP

将下面条目加入客户端的 MCP 配置，路径替换为本目录的绝对路径：

```json
{
  "mcpServers": {
    "team-calendar": {
      "command": "node",
      "args": ["/absolute/path/calendar/server/mcp.mjs", "--workspace"]
    }
  }
}
```

先调用 `team_calendar_read` 取得项目、成员 ID 和 revision，再调用 write。工具只接受结构化计划；自然语言任务拆解由调用它的 Agent 完成，本服务不会自行调用或付费使用模型。

示例 write 参数（请使用实际读取的版本与成员/项目 ID）：

```json
{
  "requestId": "weekly-import-unique-001",
  "expectedRevision": 0,
  "action": "upsert",
  "sourceKey": "assigned-plan",
  "plan": {"sourceId": "week-2026-11-16", "title": "本周计划", "weekStart": "2026-11-16"},
  "tasks": [
    {"sourceId": "TASK-001", "title": "完成脚本与分镜", "projectId": "brand", "assigneeId": "tao", "deliverable": "确认版分镜稿", "dates": ["2026-11-16", "2026-11-17"]}
  ]
}
```

`sourceKey + sourceId` 定位同一任务；同一任务的日期记录引用服务返回的 task_id。若明确传入 `dates`，表示替换该任务的日期列表；省略则保留原安排。省略 status 时保留原状态，新任务默认待开始。重复提交同一 requestId 和相同请求体返回原回执；同一 ID 携带不同内容会被拒绝。网络超时先调用 operation 查回执，不能盲目换 ID 重发。

页面导入可使用便于填写的格式：

```text
W001 | 完成脚本与分镜 | 品牌短片 | 涛子 | 2026-11-16,2026-11-17 | 确认版分镜稿
W002 | 素材整理 | 品牌短片 | 周洋 | 2026-11-18 | 素材包
```

## 验证与边界

完整包测试：`node --test tests/*.test.mjs`。覆盖唯一身份、重复来源/请求、事务回滚、并发冲突、只读权限、跨站拒绝、真实 MCP stdio、实时变更事件、重开数据库，以及插件注册/范围限制/卸载。

浏览器实测包括保存任务、导入周计划、拖拽改期并核对同一任务 ID、搜索、项目成员设置入口、日周月切换、键盘焦点、明暗主题与 390px 窄屏。真实 MCP 写入后，两份打开的浏览器页面自动出现同一任务。

当前服务绑定回环地址，两个客户端指本机验证客户端。**尚未部署团队跨设备共享服务，未接通真实任务中心读取／写回与自动拆分流水线。** 团队部署需要共用服务地址、各成员凭据及 HTTPS 入口，不能把各电脑分别运行的数据库称为已经共享。

本版没有加入工时负荷计算、人机等待分类、自动锁定与重排策略，符合本次确认范围。

## 开发

`npm install` 后运行 `npm run build` 可重建插件与预览。源码统一在 `src/`；插件自带 React 来自 Buzz 的 ctx.react，浏览器预览使用 React 19.2.0。构建输出的 plugin.js 是无运行时 import 的单一 ES 模块。构建依赖全部来自本工程，使用 `npm ci` 按 package-lock.json 安装；不再依赖其他本机项目的 node_modules。

## 1.0.1：会议与点击交互

点击任务或整月排期条先打开速览卡，再点击编辑打开详情。速览支持 Esc、关闭后恢复原任务焦点；编辑表单内容独立滚动，底部保存按钮不覆盖字段。

新建安排时选择「会议」，填写日期及同日开始/结束时间、负责人、参会成员、线上方式/线下地点、已有 HTTPS 入会链接、提前准备/进会时间及提醒分钟数。同一会议显示在负责人和参会成员行，仍引用同一 task_id。普通任务和会议共用 UI、HTTP 和 MCP 的写入口。会议暂不自动发送邀请或读取外部会议状态。

腾讯会议自动创建 **尚未接入**，当前运行时没有可调用的创建工具。本版展示未连接状态和禁用的自动创建按钮，不会生成虚假会议号。可粘贴已有链接并通过「进入会议」打开。后续需实现开放平台连接、服务端凭据保管、创建/更新/取消及失败查询后，再启用按钮。

本机提醒默认关闭；关联当前成员后，点击顶部时钟或会议速览里的「开启本机提醒」，本人负责或参会的会议会在约定时间显示页面提醒，提前进会时间也会提醒。未绑定连接不能启用个人提醒。若需系统通知，可在会议速览单独点击「允许系统通知」并通过浏览器授权。定时器每 15 秒检查一次；仅捕获触发后 60 秒内的提醒，后台标签页被暂停时可能错过。页面关闭、休眠、离线后的后台投递及 Buzz 推送尚未实现。不会自动打开摄像头、麦克风或代替成员进入会议。

MCP 会议任务示例（并入已有 write 请求的 tasks）：

```json
{"sourceId":"weekly-meeting","title":"项目周会","kind":"meeting","projectId":"brand","assigneeId":"tao","meeting":{"provider":"tencent","url":"","location":"线上 · 链接待补充","participantIds":["zhou","moo"],"joinBeforeMinutes":5,"reminderMinutes":10},"dates":[{"date":"2026-11-18","start":"17:00","end":"18:00"}]}
```

截图中的会议属于明确标记的示例，没有实际创建腾讯会议或发送邀请。

## 1.0.2：明亮与清晰的视觉调整

默认浅色预览使用白色内容与侧栏、轻量分隔线，配合 Buzz 的强调色选中态。周历恢复浅色项目卡片，放大日期和任务标题，移除卡片上的泛化占位说明。原有中性色主按钮和宿主语义颜色继承保持一致。

顶部统一为日／周／月三个入口。月历默认展示按日期的团队安排，卡片显示负责人、明确时间和任务标题；更多安排可进入当日列表。「按成员」布局在左侧完整显示任务名称、项目、状态和时间，右侧只承担日期定位，避免把标题压缩到单日短条里。

侧栏小月历默认收起在「跳转日期」中。速览卡按实际高度校正位置，避免底部按钮被裁切；编辑表单继续保留独立滚动区和固定保存区。

本次没有改变任务身份、会议字段、MCP 保存规则和接入边界。腾讯会议自动创建、页面关闭后的后台提醒、团队跨设备服务和 Buzz 原生安装仍待完成。

## 1.0.6：身份绑定与流程验收

「只看我」使用服务返回的当前成员，不再固定为 Moo；未绑定时禁用个人筛选与提醒。Buzz 当前用户必须匹配本机已配置连接，切换身份会清除旧筛选与草稿。连接身份是本机信任边界，不是远程签名认证；个人筛选不提供成员级数据隔离。

修复线上会议改成线下后残留入会链接，以及新建遇到版本冲突后无法恢复提交的问题。新建冲突时可保留草稿并载入最新版本；编辑已有任务需要明确载入最新内容再修改。配置与身份边界见 [验收报告](docs/ACCEPTANCE_V106.md)。
