# 好望水历史快照：独立访问范围

这是接入的第一批候选代码，不代表 NAS 数据连接器或 Work 端到端读取已经上线。

## 权限与客户端

`haowangshui` 使用单独的 `/opt/opcb-knowledge/haowangshui-members.json`，格式和文件权限与原 `members.json` 相同（受控父目录、普通文件、0600）。它只授权好望水来源，不赋予原四源权限。两个名单均按每次请求验签所得的 **owner** 检查；仅有 Agent caller 入名单不能通过。旧 Bearer 不可读此来源。缺失、损坏、权限过宽或删除成员均立即拒绝后续私有读取，原四源不受其影响。

`catalog` 只返回该身份获授权的来源。桌面 TS 协议、Rust 原生请求和 Agent 工具同时增加新来源，页面复用现有 `FullPageSurface`、`NavigationItem` 与 `Dialog`，只呈现服务器返回的来源。名单中的真实公钥由管理员按用户确认单独部署，不进入仓库。

**切换顺序：先验证并交付支持新来源的客户端，再启用线上私有名单。** 旧客户端只认四源，不能在其仍运行时给它返回第五源。准备阶段不能把两个新账号加到原团队名单来绕过此顺序。

## 离线导入契约

NAS 导出器应只读授权归档目录，输出完整文本快照，不发送原二进制附件：

```json
{
  "version": 1,
  "complete": true,
  "snapshot_date": "2026-09-18",
  "documents": [
    {"object_key": "docx:stable-object-token", "title": "示例", "content": "正文、表格文本与来源目录"}
  ],
  "facts": {"failed_objects": 44, "parser_failures": 0}
}
```

管理员在独立候选目录用 `python3 archive_snapshot.py --root <private-state> <snapshot.json>` 导入。HTTP 接口仍然只有读操作，客户端不能指定导入路径或写索引。完整文件最多64MiB、20,000条，每条正文最多1MiB；空集、重复对象、格式异常或不完整快照拒绝整批替换。导出器必须显式报告上游失败、附件未解析、正文超限等缺口，不能把这些缺口解释为完整原飞书。

文档 ID 根据稳定 `object_key` 生成，改标题或重复导入不改变 ID；归档快照事务性替换独立来源，不改原四源。导入时记录文件 SHA256 与导出日期，业务创建/更新时间未知则留空。历史快照不套用实时来源15分钟过期规则；它的 `ready` 仅表示已导入快照可查询，不表示实时飞书已同步。

引用 URL 是固定的归档文档定位地址。浏览器 GET 只显示文档编号和 Work 读取说明，不返回标题、正文或附件，也不检查该编号是否存在；真实正文仍通过已验签的 `get` 请求读取。该定位页面不是附件下载能力。

## 待完成的真实链路

NAS Office/PDF 等解析导出器、指定目录复制、受限私有通道、自动传输与附件中转尚未实现。先以合成快照验证服务边界，再以少量经确认资料验证搜索与读取。旧知识服务、索引、共享服务及源盘不因候选代码准备而改变。

当前验证入口为本中心 npm run ci，不执行旧宿主 TS/Rust 检查。Python HTTP 测试覆盖独立名单、owner/caller 边界、撤权、损坏名单、旧 Bearer 和非成员拒绝；实际所有者签名与 NAS 真实文件读取仍需部署后验收。
