# 身份服务部署与维护

本仓库维护代码；运行配置、原始资料、账号凭据、个人公钥管理员名单、授权数据库和设备数据库不进入仓库或安装包。

1. `npm ci` 后运行 `npm run build:knowledge`，生成两个自包含插件与服务验签 bundle。运行 `npm run ci` 完整检查。Node 构建环境要求 20.19+；服务解释器需要 SQLite FTS5 和 hashlib.scrypt（旧协议兼容测试用）。可用 `OPCB_KNOWLEDGE_PYTHON` 选择 Python。
2. 将候选源码与验签 bundle部署到独立版本目录。指定现有只读索引 `--root`、新的私有策略目录 `--policy-root`、核实后的社区签名公钥 `--community`、明确个人管理员 `--admin`、受控 `--node/--verifier`。服务以既有受限知识服务账号运行，仅监听 127.0.0.1:3037。
3. 空策略库首次初始化默认目录和管理员读取权限，其他人默认无权限。后续重启不覆盖现有权限/名称。先校验健康、匿名拒绝、真实原生绑定、目录/分页/搜索/正文、源隔离、个人撤权与 Agent 不能管理，再启用固定 api/v2 路由。保留旧密码端点直到当前客户端完成迁移，随后在明确切换回执中退役；不能在新链未验证时停用现用入口。
4. 原生安装审核固定中心来源和完整提交；批准后核对实际 revision、active/error 和原生绑定流程。读取插件与管理插件分别审核。另一台机器需要一次设备绑定，个人ACL无需重建。桌面通过不能声称移动端通过。
5. 失败回退只恢复本轮候选服务/新增路由，保留策略与设备数据库，不重置索引/成员/密码/会话，不重启原采集与其他业务。Caddy 修改前保留当前备份、只补本轮路由并校验；禁止用旧整份配置覆盖并行变更。

移除本机绑定只移除设备上的密钥/缓存。服务器按个人关闭可立即拒绝后续所有设备及其Agent访问。已经显示或被调用方复制的资料无法追回；撤权保证后续请求与缓存重新读取拒绝，不宣称能收回既有副本。

服务当前未实现托管 Agent 跨设备密钥同步；本机新增 Agent 可复用同个人读绑定，在新设备首次接入时需原生签名绑定，无需管理员逐个登记 Agent。设备请求归因到绑定签发者，不能冒称逐次获得当前某个 Agent 的原生签名。
